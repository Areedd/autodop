# AutoDOP 负载修正与实例级并行度调整（DD03/DD04 P0 缺口）

## Goal

补齐 AutoDOP 设计中尚未实现的三个 P0 功能缺口：

1. **负载修正**（DD03 §4.2）：在线决策对策略网络输出的 DOP 按节点实时负载做有界修正，避免在高负载节点上叠加并行度。
2. **实例级并行度调整**（DD04）：分布式环境下，扫描类片段在各 BE 上的实例并行度随所在节点资源状况差异化调整（资源紧张者下调，资源充裕者保持基准）。
3. **轨迹扩展**（DD04 §1.3）：执行轨迹记录基准并行度、调整后实例并行度与最终下发并行度三份数据。

三个缺口共享同一份节点资源数据（资源视图），构成一个垂直功能切片。现有单机决策链路（策略推理、决策窗口、安装）原样沿用，不改变其结构。

## Requirements

### R1 资源视图（DD04 §2.3、§3、§5.2 的基础）

- 按周期（默认 2s）获取各 BE 的 CPU 使用率与内存压力，复用既有指标通道（BE 已通过 agent report 上报 `cpu_used_permille` / `mem_used_bytes` / `mem_limit_bytes` 到 FE 的 `ComputeNode`），不新增 BE 侧工作。
- 按节点聚合，输出归一化资源状况：CPU 使用率（0–1）、内存使用率（0–1）、数据新鲜度标记。
- 资源数据过期或缺失的 BE 按中性值处理（视为资源充裕，不调整），不阻塞查询。
- 同一份资源视图同时供负载修正（DD03）与实例调整（DD04）消费，保证两处口径一致。
- 可配置项：采集周期、EWMA 平滑系数、死区阈值、缩放因子下限。

### R2 负载修正（DD03 §1.3、§4.2）

- 在线决策（策略网络输出后）按目标 worker 的实时负载对 DOP 做有界缩放。
- 平滑：原始采样经 EWMA 过滤瞬时抖动（平滑系数默认 0.25）。
- 死区：负载低于阈值（CPU 0.4、内存 0.65）时因子为 1，不调整；超过阈值后因子随负载线性下降，满载处触底 0.1。
- 每个 worker 的因子取 CPU 与内存两个维度的较小值；每个 fragment 取全部目标 worker 因子中的最小值（按最弱节点处理）。
- 修正后的 DOP 取候选集中最接近的值，且不低于 1。
- 修正按 fragment 粒度施加，同一 fragment 所有实例一致（保持 exchange 路由一致）；只在实例化前一次性施加，不引入震荡。

### R3 实例级并行度调整（DD04 §1.3、§2、§4）

- 可调整片段判定（三条须同时满足）：无上游数据交换输入（无 incoming exchange 边）；不属于 colocate 拓扑；不属于 bucket shuffle 拓扑。
- 对可调整的扫描类片段，按各目标 BE 的资源状况调整所在实例的并行度：
  - 资源紧张的 BE 上实例并行度有界下降，紧张程度越高下降越多；
  - 调整只降不升（资源充裕的 BE 保持基准并行度）；
  - 结果取候选集内最接近的值，且不低于 1；
  - 调整幅度不超过上限（可配置）；
  - 同一 BE 上的多个实例按同一规则调整，保持节点内一致。
- 非扫描类片段（有上游输入）与 colocate/bucket shuffle 拓扑中的片段保持片段级一致并行度，不破坏 exchange 路由。
- 调整发生在放置确定之后、实例化之前的决策窗口内，与 DOP 决策共用同一时机与同一份资源信息。

### R4 轨迹扩展（DD04 §1.3、§5.1）

- 执行轨迹记录每个实例的：基准并行度（决策输出、未做实例级调整前）、调整后实例并行度、最终下发实例并行度。
- 与既有 trace 字段（request/response/decided/installed/actual_instance_dop）兼容，不破坏现有离线训练流水线（data.py 的 `sample_from_trace`）。

### R5 稳定性与可配置性（DD03 §1.4、DD04 §1.4）

- 决策服务不可达、超时、协议不匹配或返回非法值时，查询显式失败，不静默回退（沿用现状）。
- 资源数据缺失或过期时调整退化为不调整（保持基准并行度），不阻塞查询。
- 配置项：负载采样周期（默认 2s）、EWMA 平滑系数（默认 0.25）、死区阈值（CPU 0.4 / 内存 0.65）、缩放因子下限（0.1）、实例调整幅度上限、候选 DOP 上限（沿用 `auto_dop_max_dop`）。

## Acceptance Criteria

### AC1 资源视图（R1）

- [ ] FE 侧资源视图模块可读取各存活 BE 的 CPU 使用率与内存使用率（复用 `ComputeNode` 数据），数据过期/缺失的 BE 标记为不新鲜并按中性值处理。
- [ ] 资源视图以统一接口向负载修正与实例调整两处提供按节点查询能力。
- [ ] 单测：采样聚合、EWMA 平滑、缺失/过期处理行为正确（DD04 §6.3 资源视图测试）。

### AC2 负载修正（R2）

- [ ] Python 侧实现负载修正纯函数：死区判定（阈值以下因子=1）、超阈值线性下降且不低于下限、CPU/内存两维取较小值、多目标 worker 取最小因子、修正后 DOP 落在候选集内且不低于 1。
- [ ] 决策请求携带 worker 负载数据（FE 资源视图 → 请求扩展），负载缺失时修正退化为不修正。
- [ ] 单测覆盖 DD03 §6.3 负载修正测试全部用例（平滑、死区、下限、最弱 worker、候选集合法性）。
- [ ] 在线决策路径中修正与策略推理在同一次安装完成，决策耗时仍在 50ms 预算内（trace 记录 decision_latency_ms 可查）。

### AC3 实例级调整（R3）

- [ ] FE 侧在决策窗口内（materialize 之后、finalizeDAG 之前）对可调整扫描片段按 BE 资源差异化设置实例并行度。
- [ ] 可调整性判定正确：有上游输入、colocate、bucket shuffle 的片段一律不做实例级调整（单测断言其实例并行度保持片段级一致）。
- [ ] 调整只降不升、幅度有界、结果落在候选集内且不低于 1；同一 BE 的多个实例调整一致。
- [ ] 调整后的实例并行度正确反映到执行（BE 侧按实例 DOP 创建 driver），查询结果正确性不受影响（集成实验验证）。
- [ ] 单测覆盖 DD04 §6.3 调整规则测试与路由安全测试。

### AC4 轨迹扩展（R4）

- [ ] trace 记录实例的基准并行度、调整后并行度、最终并行度三份数据；`sample_from_trace`（Python）对新旧 trace 格式均兼容。
- [ ] 集成实验：开启 AutoDOP 执行查询后，trace 中三份数据完整且数值关系正确（基准 ≥ 调整后 ≥ 最终，且调整后 == 最终当无下游钳制时）。

### AC5 端到端实验（DD03 §6.1、DD04 §6.1）

- [ ] 构造节点负载不均衡场景（部分 BE 预置高负载）：高负载 BE 上的扫描实例并行度低于低负载 BE，且查询延迟不劣于不做调整的基线。
- [ ] 开启与关闭负载修正对比：高负载下修正通道生效（DOP 收缩），低负载下不产生扰动。
- [ ] 修正+调整同时开启时，两处消费同一资源视图、调整方向一致。

## Notes

- 范围限定：只实现上述三个缺口；不做 DD02 评估脚本补全（排序准确率评估，属 P1）、不做 OLTP 基准（P2）。
- 环境：本地 FE（`output/fe`，172.21.0.1:9030）+ 3 个 BE（starrocks-be1/2/3，3.5.17），TPC-DS SF10/SF100 等数据已加载。
- 决策服务（`autodop_server.py`）实验时启动在 18080。
- 参考设计文档：DD03 §1.3/§4.2/§5.3/§6.3、DD04 全文。
