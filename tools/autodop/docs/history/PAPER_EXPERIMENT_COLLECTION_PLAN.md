## 实验与所需证据

1. **Q1 模型质量和泛化**：五种模型（XGBoost、图回归有/无竞争边、图排序有/无竞争边），
   三个随机种子，固定30轮训练。使用相同未参与训练的配置库评价pair accuracy、top-3、
   相对最佳已观测配置的regret；回归模型另报RMSE/MAPE。归一化仅使用训练样本。
2. **Q2 搜索质量**：SF10验证模板，Random/Greedy/Vanilla MCTS/Optimized MCTS，
   25/50/100/200/500候选评分预算，三个随机种子。被选配置实际执行3次；重复配置可共享
   同一组实测证据，但不能重复宣称独立测量。空间不超过256的小计划完整枚举后才可称oracle。
3. **Q3 单查询对照**：Native、全局DOP1/2/4/8/16、随机合法配置、静态策略、带负载修正策略、
   固定的回归/XGBoost候选，正式5次，另预热1次；轮次内打乱方法顺序。报告宏平均、P90、
   每模板胜负、失败和fallback，训练内与留出结果分开。候选域受限的离线基线明确命名。
   预选配置按具体SQL绑定并再次核对实际计划特征，避免不同SQL因特征相同而串用配置。
4. **Q4 并发与负载适应**：TPC-DS SF100全套已验查询，1/10/20/40个客户端，Native/
   静态策略/负载策略，3个独立完整重放轮次加预热。记录实际完成量、吞吐、P90/P95、失败，
   同时采集BE原始指标。3轮置信区间只作有限重复的描述，不夸大统计显著性。
5. **Q5 案例与DOP敏感性**：预先选择Q22/Q51/Q72，Native和各策略及静态DOP对照，
   正式5次，保存完整query profile、每片段DOP与算子计数。片段重叠时间不做可加分解。
6. **Q6 受控消融**：full/no_comp/regression_loss/random_search均使用同样搜索预算、
   同样150轮蒸馏、相同初始化规则（对应教师编码器+固定分类头种子）与学习率，再按5次正式执行比较。仅切换被研究的组件；
   不把固定配置基线直接称为完整流程的组件消融。
7. **Q7 开销**：复用上述采集记录离线拟合/搜索成本、候选评分次数、服务端决定耗时、
   FE HTTP往返决定耗时。只有profile/trace明确提供的分项才报告，不编造特征抽取或等待百分比。

## 运行与隔离

- Run root: `tools/autodop/runs/paper_campaign_20260905/`。
- `experiment_plan.json`：完整参数矩阵及记录时机；SQL与划分在采集前固定。
- `manifests/`：各语料原始SQL来源/hash、逐条变体和固定用途。
- `perturbations/`：原始trace、native/probe/warmup/measured完整事件。
- `steps/`：后续命令从只读Python源码快照执行，保留hash、stdout/stderr与退出状态。
- `environment/`：源数据库重建、审计、依赖、硬件和测试证据。

数据库导入和实测不并行；初始训练/蒸馏也必须结束后才开始外部耗时采集。模型复用评估
全部完成后才开始后续搜索与方法实测。离线模型计算绑定BE所用0–23号CPU之外的CPU。SF100与TPC-H
源文件共227GB级，完整哈希/导入/关联审计及大量真实SQL需要持续较长时间。未结束的后台
进程不能作为采集完成的依据。

正式对照采集器（包含客户端与策略HTTP服务）使用CPU27–34的8个物理核心，Torch单次
推理线程数为1；训练种子分别使用CPU24/25/26。该设置只限制允许运行的CPU，不代表主机
其他进程无法共享。正式对照开始前纠正了原先单核采集器设置，并保留等待队列的中止记录。
采集器自身CPU、RSS、线程数与affinity另存，辅助识别负载生成器瓶颈，不当作BE负载指标。
