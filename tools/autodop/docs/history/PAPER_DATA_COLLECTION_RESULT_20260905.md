## 划分、噪声与敏感性分析

SF10 固定训练/验证/测试为 63/20/20 条 SQL，按数字模板家族分组，对应 60/20/19 个家族。
配置数为 2,016/640/640，排序对为 14,314/4,048/3,539。训练仅使用训练分区；模型训练
30 epochs，种子 0/1/2 全部保留。外部语料配置耗时不参与拟合。

排序对要求中位数差距至少 3%，且重复测量区间不重叠。SF10 剔除 16,689 个区间重叠的
候选对；配置耗时 CV 中位数 3.95%、P90 9.04%，247 个配置 CV 超过 10%。噪声记录保留。

训练 Q42/测试 Q52、训练 Q63/测试 Q53 存在精确计划特征重叠。保留原始固定划分结果，
另外排除测试 Q52/Q53，完成 **18 SQL、576 配置、3,171 排序对**的事后敏感性分析：
复用全部 15 个模型，不重训、不重新搜索。Q24a/Q24b 仍是同家族重复特征，不视为独立家族。
“精确特征未见”不等于完整语义或结构家族完全互斥。

## 实际结果及能支持的结论

### Q1：模型排序

下表为三个训练种子的排序准确率均值，不是最佳种子。

| 模型 | SF10 固定测试 | TPC-DS SF100 | TPC-H SF10 | TPC-H SF100 |
|---|---:|---:|---:|---:|
| GT_pair_comp | 0.8431 | 0.8203 | 0.7464 | 0.6857 |
| GT_pair | 0.8353 | 0.8175 | 0.7298 | 0.6334 |
| GT_reg_comp | 0.7272 | 0.7441 | 0.6978 | 0.6251 |
| GT_reg | 0.7103 | 0.7138 | 0.6697 | 0.6253 |
| XGBoost | 0.7426 | 0.7478 | 0.7342 | 0.7796 |

完整模型在严格 18 SQL 测试中的准确率为 0.8289；XGBoost 为 0.7417。
完整模型在 TPC-H SF100 低于 XGBoost，不能声称跨工作负载全面领先。
SF100 与 SF10 使用相同 SQL 模板，规模迁移不等同全部 SQL 未见。

### Q2：搜索

预算为 25/50/100/200/500 次候选评分，算法为随机、贪心、原始 MCTS、优化 MCTS。
搜索在验证集完成，选择配置后真实补测三次。只有 Q3 的 256 个合法配置全部测完，
可作为穷举 oracle；其他查询仅以已测配置并集最优值为参考。

预算 500 时，平均已测集合 regret：贪心 0.1091、优化 MCTS 0.1248、随机 0.1277、
原始 MCTS 0.1310；区间存在重叠，不能宣称优化 MCTS 优于所有基线。
置信区间按查询聚类、先聚合同查询种子，额外 attention 调用与候选评分预算分开记录。

### Q3：完整方法当前没有稳定的总体加速

以下为每查询五次客户端完整取回耗时中位数，再对“Native/方法”取几何平均；大于 1 才是加速。
“全部”行含原固定训练查询，仅 SF10 测试行用于未见模板结论。

| 对照范围 | 静态完整策略 | 加负载修正策略 |
|---|---:|---:|
| TPC-DS SF10 全部 103 SQL | 0.9440 | 0.9469 |
| TPC-DS SF10 固定测试 20 SQL | 0.9555 | 0.9438 |
| TPC-DS SF100 接受的 102 SQL | 0.9961 | 1.0030 |
| TPC-H SF10 全部 22 SQL | 0.9023 | 0.9021 |
| TPC-H SF100 接受的 21 SQL | 0.8702 | 0.8759 |

静态和负载策略每轮分别实际应用 SF10 TPC-DS 25/103、SF100 TPC-DS 26/102、
SF10 TPC-H 15/22、SF100 TPC-H 17/21 条查询，其余多为低置信度回退。
排序准确率较高尚未转化为端到端收益；需要进一步研究蒸馏保真度、置信度与决策开销，
这些是后续改进方向，不把本轮数据重跑到得到加速为止。

14,880 次正式执行中 15 次失败均为 SF100 Q70 的 GT_pair/GT_reg/XGBoost 冻结配置
因 11 片段变为 10 片段而被拒绝；预热另有 3 次同类失败。SQL 即使正确回退执行，
该次固定配置干预仍记为失败。这些成本模型基线是在已测配置中预测预选并冻结，
不是对新计划在线重新搜索；不能据此断言模型无法预测新计划。

### Q4：并发成功率与容量限制

每个“并发数–方法”有 306 次正式执行（102 SQL × 3 次）。表中为正式失败数。

| 客户端 | Native | 静态策略 | 负载修正策略 |
|---|---:|---:|---:|
| 1 | 0 | 0 | 0 |
| 10 | 27 | 31 | 24 |
| 20 | 64 | 58 | 56 |
| 40 | 139 | 130 | 133 |

正式失败合计 662，预热失败 204，主要为 180 秒查询超时及 BE 内存超限。
每轮成功吞吐、失败数量和成功查询延迟分布分别保存。失败查询不能从容量分母消失，

10/20/40 客户端没有满足该条件的完整对照轮，不能报告完整工作负载的显著吞吐加速。

### Q5：回退案例与实际应用案例都保留

原定 Q22/Q51/Q72 获得 108 份 profile（90 正式、18 预热），策略均因低置信度回退。
它们可分析固定 DOP 与回退行为，不能用于证明策略已实际改变执行。

### Q6：受控消融

四组策略使用匹配教师搜索预算 500、蒸馏 150 轮、种子 0、相同学习率设置，各自教师编码器

## 环境、复现和解释边界

- 三个 BE 3.5.17-041cd01 容器位于同一物理主机，每 BE 8 个 CPU、16 GiB 容器上限，
  BE 报告内存限额约 11.52 GiB；不能写成草稿中的独立大内存服务器。FE 为当前项目构建。
- CPU 归一化见[官方 3.5.17 源码](https://github.com/StarRocks/starrocks/blob/3.5.17/be/src/util/cpu_usage_info.cpp)：
  分母使用 `hardware_concurrency()`，没有按容器 8 CPU 配额重标度。若运行时分母为 192，
  单 BE 的 8 CPU 满载也仅约 4.17%，低于默认 40% 阈值。运行时分母未独立探测，
  这是源码与部署支持的推断；本部署不能单独证明 CPU 压力修正有效或无效，内存分支另论。
  [源码与部署审计](runs/paper_campaign_20260905/environment/load_metric_scope_audit.json)。
- 基础扰动连续运行同 SQL 的多个配置；端到端对照按整套语料运行方法轮次，种子固定的方法
  顺序打乱、同次重复的方法共用查询顺序。没有清空或锁定 OS/BE 缓存，预热不保证 SF100
  全工作集驻留内存。不能跨阶段直接比较绝对耗时，也不能称为严格冷缓存或全热缓存实验。
- 标签和搜索使用 FE trace 耗时，端到端和并发使用客户端完整取回耗时，两个口径分开。
- 所有正式步骤有只读源码快照、参数、依赖指纹、退出状态和日志。数据库源哈希与导入检查
  支持可追溯性，但不是独立 SQL 正确性 oracle 或正式 TPC 认证。
- 整合版实验计划在初始部分 SQL 执行后落盘，`frozen_before_results=false`；不能称为完整
  预注册。事后特征敏感性分析及适用性案例均明确标记，未修改原划分、原模型或原测量。

SF100 Q3 在全部测量结束后发生空闲管理连接失效，导致原步骤恢复 FE 参数失败、非零退出。
已在核对全部 7,344 个执行位置后，用新连接恢复并逐项读回五个原参数；归档恢复前元数据
及 SHA，保留原始步骤失败状态和原始测量，不重跑基准查询。后续阶段使用新连接恢复，
全部恢复成功。[恢复审计](runs/paper_campaign_20260905/evaluations/Q3_tpcds_sf100/finalization_recovery.json)。

工具回归最后一次为 **133 项测试、41 个子测试通过**，覆盖过期管理连接恢复；测试期间暂停
性能采集。交付阶段另外核对所有导出表源哈希、CSV 哈希、行数与无损 JSON 列，失败原始记录
及正式/预热/参考/探测计数完成对账。

后续应基于这批固定证据调整论文结论，并优先改进蒸馏保真度、策略回退开销与资源指标口径。
本轮采集已结束；后续改进应另开实验版本，保留本轮结果作为对照。
