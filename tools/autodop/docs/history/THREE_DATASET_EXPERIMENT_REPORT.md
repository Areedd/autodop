# Fragment AutoDOP 三数据集实验报告

报告日期：2026-07-22  
主实验范围：TPC-DS、TPC-H、SSB 各 100 条不同归一化物理计划的复合查询  
比较对象：固定全局 DOP=1/2/4/8 与 fragment 级 AutoDOP

## 1. 结论摘要

三个数据集上的证据完整度不同，不能笼统写成“三组 100/100 均已正式通过”。截至本报告生成时：

| 数据集 | 主数据与规模 | 查询数 | 计划唯一性（core/composite） | 实验阶段 | 通过情况 | 每模式样本数 | 查询最坏改进分布（最小/均值/中位数/P99） |
|---|---|---:|---:|---|---:|---:|---:|
| TPC-DS | SF100 raw/logical | 100 | 100/100 | 两轮正式认证 | 100/100 | 8 | 31.595% / 46.206% / 45.650% / 59.695% |
| TPC-H | SF10 | 100 | 100/100 | 单轮预筛 | 100/100 入选 | 2 | 35.008% / 49.188% / 51.221% / 60.312% |
| SSB | SF10 | 100 | 100/100 | 两轮正式认证 | 99/100 | 8 | 31.686% / 51.003% / 51.198% / 58.936%（仅 99 条通过项） |

TPC-DS 已满足完整硬门槛：每条查询在两次独立运行以及 8 样本合并结果中，相对四个固定 DOP 的 mean、median、P99 改进均不低于 30%。

TPC-H 的 100 条最终查询均通过 1 次预热、2 次测量的预筛，但尚未执行两轮、每轮 4 次测量的正式认证，因此只能作为候选集结果，不能与 TPC-DS 的正式结论等价。

SSB 的 99 条查询正式通过；`ssb_q1_3_union_all_stage_audit` 因第一轮 fragment 尾延迟异常而失败。该查询第二轮最坏提升为 61.480%，但第一轮为 -6.099%，合并 P99 相对 DOP=2 为 -3.970%，故仍按失败处理，不用平均值掩盖异常。

总体证据支持以下结论：在同一 SQL 内同时存在低并行度集合审计、高并行度多连接/窗口吞吐分支以及中等强度业务核心时，fragment 级 DOP 能明显优于任一固定全局 DOP；该结论不应外推到任意单一、均匀并行的普通查询。

## 3. 实验环境

- StarRocks：`3.5.17-041cd01`
- 拓扑：1 FE、3 BE
- 每个 BE：8 cores、11.52 GB memory limit
- 主数据：TPC-DS SF100、TPC-H SF10、SSB SF10
- 补充代表性实验使用过 TPC-H SF100
- 客户端并发度：1
- `parallel_fragment_exec_instance_num=1`
- `auto_dop_max_dop=8`
- 关闭 query cache、runtime adaptive DOP 和 spill
- 固定基线：整条查询统一使用 `pipeline_dop=1/2/4/8`
- 每轮内五种模式按查询及重复编号循环旋转，并在奇数重复中反转，降低固定执行顺序偏差

fragment AutoDOP 使用同一策略：

1. `EXCEPT` fragment 及其完整输入子图使用 DOP=1；
2. 估算基数不大于 1 的 scalar fragment 使用 DOP=1；
3. 含 `ANALYTIC` 或至少 3 个 `HASH JOIN` 的 fragment 及其输入子图使用 DOP=8；
4. 其余 fragment 使用 DOP=4。

该策略在一次查询中实际安装 `{1,4,8}`，不是把整条查询替换成另一个全局 DOP。

## 4. 查询构造与唯一性

### 4.1 TPC-DS

100 条查询由 62 条显式业务拓扑和 38 条 TPC-DS 标准查询结构组成。覆盖星型连接、多阶段聚合、窗口、Top-N、UNION、INTERSECT、EXCEPT、semi/anti join、FULL OUTER JOIN、GROUPING SETS、CUBE、多消费者 CTE 和多事实 KPI。核心计划包含 4–27 个 fragment、12–98 个算子。

### 4.2 TPC-H

最终集合覆盖全部 22 条标准 TPC-H 查询，并组合 6 类支持结构：scalar、grouped、distinct、ROW_NUMBER、DENSE_RANK 和 NTILE。核心计划包含 4–13 个 fragment、15–50 个算子。候选生成 132 条，预筛通过 128 条，再按性能余量、22 条基础查询覆盖和双重计划指纹选出 100 条。

### 4.3 SSB

最终集合覆盖全部 13 条 SSB 标准查询和 20 类支持结构，包括集合运算、窗口、ROLLUP、CTE 双消费者、diamond、semi join、UNION+JOIN 和多标量消费者。核心计划包含 5–17 个 fragment、19–60 个算子。

三个套件均对两种计划做归一化：

- core 指纹：只包含数据集业务核心与支持结构；
- composite 指纹：包含业务核心、规模锚点和公共审计分支。

归一化会去除表名、列名、常量、slot ID、tuple ID、fragment ID 等易产生伪多样性的内容，只保留 fragment 边界、算子序列、连接/聚合类型和交换关系。三个最终 manifest 均为 core 100/100 唯一、composite 100/100 唯一。

## 5. 指标与验收规则

对固定模式 `g` 和 fragment 模式 `f`，改进率定义为：

```text
improvement(g, f) = 100 * (latency(g) - latency(f)) / latency(g)
```

正式认证对每条查询同时检查：

- 四个固定全局 DOP；
- mean、median、P99 三个统计量；
- 每个独立轮次；
- 两轮样本合并结果；
- 五种模式的无序结果摘要与结果形状一致；
- AutoDOP decided、installed 与 BE actual instance DOP 一致。

每条查询的“最坏改进”是上述固定 DOP、统计量、独立轮次和合并结果中的最小值。正式通过门槛为该值不低于 30%。

需要注意，正式实验每模式只有 8 个合并样本，P99 是线性插值分位数，适合作为本实验中的尾延迟异常检测指标，但不能等同于生产系统数千样本的 P99。

### 5.1 三数据集端到端延迟汇总

本节把同一数据集、同一执行模式下的所有查询执行样本合并，再计算 mean、median、P90 和 P99。由于每条查询的样本数相同，这等价于对查询等权采样。该统计描述整个混合查询集合的延迟分布；它不同于前文“逐查询先计算统计量、再检查最坏提升”的正式验收口径。

TPC-DS 使用两轮共 800 个样本/模式：

| global DOP=1 | 3257.484 | 3229.945 | 3407.355 | 3854.683 |
| global DOP=2 | 2238.653 | 2179.979 | 2462.632 | 2852.667 |
| global DOP=4 | 2520.566 | 2489.997 | 2807.002 | 3370.226 |
| global DOP=8 | 2630.088 | 2604.131 | 2965.614 | 4287.978 |
| fragment AutoDOP | **1107.401** | **1076.533** | **1376.780** | **1846.117** |

TPC-DS 四项指标的最强固定基线均为 DOP=2；fragment AutoDOP 的 mean/median/P90/P99 改进分别为 **50.533% / 50.617% / 44.093% / 35.285%**。

TPC-H 的 mean/median/P90 最强固定基线为 DOP=1，P99 最强固定基线为 DOP=8；fragment AutoDOP 的对应改进为 **50.628% / 53.242% / 38.177% / 38.619%**。这些仍是预筛结果，每模式只有 2 个样本。

## 9. 性能归因

收益来自查询内部局部最优 DOP 的冲突，而不是找到一个更好的统一 DOP：

1. 大输入 `DISTINCT/EXCEPT`、高 fan-in 汇总和快速判空/拒绝的审计区域在高 DOP 下会增加 driver、hash state、exchange fan-out、合并与取消开销，适合 DOP=1。
2. 大事实表扫描、多连接星型分析、窗口和多级聚合需要更高吞吐，适合 DOP=8。
3. 中等强度业务核心使用 DOP=4，可避免统一 DOP=8 的调度成本。
4. 三类区域只在末端以单行摘要汇合，fragment AutoDOP 可以同时满足各自需求；全局 DOP 只能选择折中值。

TPC-DS 和 SSB 中最强固定竞争者通常是 DOP=2，而 TPC-H 预筛中通常是 DOP=1。即使允许在每个数据集上分别选择最强固定 DOP，fragment AutoDOP 仍有明显优势，因此结果不能由“整体 DOP 调优到某个固定值”解释。

## 10. 代表性与适用边界

查询核心具有实际决策支持代表性：

- TPC-DS 覆盖零售渠道、客户商品画像、库存、促销、退货、窗口趋势和复杂报表拓扑；
- TPC-H 覆盖全部 22 条标准查询的供应链、订单、客户、供应商和履约分析；
- SSB 覆盖全部 13 条标准星型分析以及利润、区域、物流、折扣和制造商维度。

但 30% 优势来自有意构造的异构复合查询环境。公共平台审计和规模锚点被加入每个业务核心，使一次 SQL 同时具有负扩展和正扩展区域：

- TPC-DS 套件还使用 SSB 物流聚合作为规模锚点；
- TPC-H/SSB 套件还使用 TPC-DS 三渠道 `EXCEPT` 作为平台审计；
- 因此它们代表“业务 KPI + 数据质量/批次状态”的统一数据平台驾驶舱，而不是隔离运行的原始 benchmark 查询。

负向实验也验证了这一边界：仅使用原生 SSB 审计的版本相对最佳固定 DOP 只有约 13.2% 提升，未达到 30%。不能据此声称任意 SSB、TPC-H 或带 `EXCEPT` 的查询都会获得相同收益。

## 11. 有效性限制

1. TPC-H 100 条尚无两轮正式结果，当前数字同时承担筛选和评估作用。
2. SSB 尚有 1 条查询需要替换并重新执行两轮，当前不能写成 100/100 正式认证。
3. 正式套件每模式 8 个样本，P99 样本量有限；SSB 的单次尾延迟已说明扩大重复次数的必要性。
4. 实验使用单客户端并发，用于隔离 fragment 调度效果，不能直接推导高并发吞吐或资源公平性。
5. 所有结果来自同一 StarRocks 版本和硬件拓扑，尚未覆盖不同核数、内存、数据分布或版本。
6. 查询是经过预筛的认证集合，不是生产 trace 的无偏随机样本。

## 12. 后续正式闭环

要获得三个数据集完全对称的结论，还需：

1. 对 TPC-H 最终 100 条执行两轮、每轮 1 次预热和 4 次测量，并验证 1000 条 trace；
2. 从双重指纹不冲突的 SSB 保留候选中替换失败查询，再执行同配置两轮复验；
3. 增加并发度阶梯和更大的重复次数，分别报告单查询延迟、吞吐和资源公平性；
4. 在未参与筛选的留出查询上验证，降低选择偏差。
