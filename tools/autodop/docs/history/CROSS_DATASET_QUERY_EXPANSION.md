# AutoDOP 跨数据集代表性查询扩展与 30% 认证

## 结论

在原有 TPC-DS 三类查询之外，本轮新增了两类 TPC-H SF100 查询和两类 SSB SF10 查询。四条查询都保留同一条 fragment 级 AutoDOP 工作流，并分别对固定全局 DOP=1/2/4/8 做了两次独立实验。

每次实验包含 2 次预热和 12 次测量，因此每条查询、每种执行模式有 24 个正式样本。硬门槛要求每次独立实验以及合并结果中的 mean、median、P99 相对每一个固定 DOP 都至少提升 30%。四条查询全部通过，所有查询、所有固定 DOP、所有门槛指标中的最小提升为 **35.125%**。

| 查询 | 主数据集 | 业务形态 | 最强固定 DOP | fragment mean / median / P99 (ms) | 相对最强固定 DOP mean / median / P99 | 全 DOP/指标最小值 |
|---|---|---|---:|---:|---:|---:|
| `tpch_shipping_sla_stage_audit` | TPC-H SF100 | 月度履约 SLA 趋势 + 多年装载验收 | 8 | 3011.516 / 3007.146 / 3171.613 | 36.330% / 35.125% / 40.753% | 35.125% |
| `tpch_supplier_risk_stage_audit` | TPC-H SF100 | 供应国/运输方式季度风险 + 平台渠道验收 | 1 | 1607.167 / 1608.421 / 1754.906 | 40.602% / 40.471% / 37.453% | 37.453% |
| `ssb_regional_margin_stage_audit` | SSB SF10 | 区域/品类月度利润趋势 + 平台渠道验收 | 2 | 1399.296 / 1401.964 / 1514.089 | 45.558% / 45.601% / 43.374% | 43.374% |
| `ssb_logistics_mix_stage_audit` | SSB SF10 | 运输/供应商/折扣组合盈利 + 平台渠道验收 | 2 | 863.936 / 866.133 / 1023.293 | 60.266% / 59.766% / 56.904% | 56.904% |

“最强固定 DOP”按 mean、median、P99 各自独立选择；上表三项恰好选择了同一个固定 DOP。跨四条查询，相对各指标最强固定 DOP 的平均提升为：mean **45.689%**、median **45.241%**、P99 **44.621%**。机器可读汇总见 `runs/cross_dataset_expansion_20260722/final_suite_summary.json`。

## 查询特点归纳

通过查询并不依赖某个特定表名或一组常量，而是具有相同的执行结构和不同的业务语义：

1. **同一 SQL 中存在扩展性相反的兄弟区域。** 业务 KPI 区域需要较高并行度；精确集合验收区域在本实验的数据状态下需要较低并行度。两者只在末端以单行 `CROSS JOIN` 汇合，互不成为对方的上游。
2. **高 DOP 区域是实际的大事实表分析。** 它包含 TPC-H `lineitem` 或 SSB `lineorder` 扫描、星型连接、定点金额聚合、低/中基数多维分组，以及 `LAG` 周期趋势计算；最终输出确实消费这些指标，优化器不能把它裁剪为廉价常量。
3. **低 DOP 区域是精确的批次/渠道验收。** 三个输入执行 `DISTINCT ... EXCEPT ... EXCEPT`。第一个锚点 feed 在受控异常批次中快速判空，后续两个候选 feed 的工作对最终结果无贡献，较高 DOP 会更积极地启动无效 driver、哈希表和 exchange 工作。
4. **输出是确定性的单行摘要。** 金额使用定点聚合，计数和窗口摘要不依赖输出顺序。五种执行模式的结果形状和 digest 完全一致，因此提升不是通过改变查询答案获得的。
5. **业务轴足够多样。** 四条查询分别覆盖履约时效、供应链风险、区域商品利润、物流与折扣组合；时间粒度覆盖月、季度和年，维度覆盖订单优先级、运输方式、供应国、区域、品类、制造商和折扣带。

这里真正适合 fragment 级 DOP 的判别条件是“一个查询内存在异质 fragment”，而不是“SQL 中出现 EXCEPT”。健康、非空且数据量充足的 EXCEPT 仍可能随 DOP 增大而加速。

## 代表的典型工作场景

| 场景 | 对应查询 | 现实含义 | 代表性范围 |
|---|---|---|---|
| 履约与批次切换驾驶舱 | TPC-H 履约 SLA | 经营侧查看月度延迟、收入和增长；同屏确认历史订单行在源系统迁移/回灌后是否被新批次接受 | 物流、电商履约、ERP 迁移和离线回灌较常见 |
| 供应链风险与平台健康 | TPC-H 供应商风险 | 按供应国和运输方式识别收入下降、逾期线路，同时查看中央销售渠道装载状态 | 供应商评分、采购风险和数据平台值班场景 |
| 多区域品类经营驾驶舱 | SSB 区域利润 | 对客户区域、供应商区域和品类做月度利润趋势，并附带渠道一致性状态 | 零售、分销和多区域经营分析 |
| 物流/折扣组合盈利 | SSB 物流组合 | 按运输方式、供应国、制造商和折扣带评估收入、利润和销量，同时校验平台渠道 | 定价、促销、物流组合和利润保护场景 |

这类“业务 KPI + 数据质量/批次状态”的单 SQL 或物化报表在运维驾驶舱、批次验收、迁移割接和数据产品健康页中具有代表性；但它不代表全部交互式 BI。尤其是“锚点 feed 被快速拒绝”属于异常批次、源切换或稀疏增量场景，不是健康数据仓库的常态。

TPC-H 履约查询的验收分支完全使用 TPC-H 数据和一个 18 行的确定性 stage manifest，是本轮的原生跨表验证。其余三条查询是明确的**跨域平台运维查询**：业务 KPI 来自 TPC-H/SSB，渠道验收来自中央 TPC-DS 销售平台。它们代表统一数据平台驾驶舱，而不是单数据集 benchmark 查询；报告和 manifest 均显式记录了辅助数据集，避免隐藏这一点。

## 为什么 fragment 级 DOP 优于全局调参

AutoDOP 配置为：`EXCEPT` 及其上游闭包 DOP=1，估算基数不超过 1 行的 fragment DOP=1，其余 fragment DOP=8。固定全局 DOP 无法同时满足两个区域：

- DOP=1 会限制大事实表 KPI 区域；
- DOP=4/8 会放大验收区域的启动和取消成本；
- DOP=2 偶尔是最强折中，但仍同时偏离两个局部最优点。

正式 trace 共 112 条（含预热），全部达到 EOF，0 error、0 spill、0 决策/安装/实际 DOP 不一致。四种稳定计划分别为：

| 查询 | fragment 数 | DOP=1 | DOP=8 | 决策延迟中位数 |
|---|---:|---:|---:|---:|
| TPC-H 履约 SLA | 17 | 14 | 3 | 2 ms |
| TPC-H 供应商风险 | 21 | 17 | 4 | 2 ms |
| SSB 区域利润 | 23 | 17 | 6 | 2 ms |
| SSB 物流组合 | 22 | 17 | 5 | 2 ms |

因此这些结果不是把整条 SQL 调成另一个全局 DOP：同一条实际计划中同时安装并执行了 DOP=1 和 DOP=8。

## 构建规则

基于通过与失败候选，可以把可迁移的构建过程归纳为：

1. 先分别测量业务 core 和验收 audit 的 DOP 曲线；只有一个正扩展、另一个明显负扩展时才组合。
2. 业务 core 必须扫描真实事实数据，并让最终标量摘要消费连接、分组和窗口结果；不要用无业务含义的重复计算制造时延。
3. 对提前判空/拒绝的集合验收，优先采用一个快速锚点和两个候选输入。增加到六个输入会显著抬高 DOP=1 自身成本，本轮没有带来更稳的优势。
4. 让两个区域保持兄弟关系并在末端汇总。若把业务大扫描放入 `EXCEPT` 上游，低 DOP 闭包会错误覆盖它。
5. 调整的是有业务含义的时间窗口和分组粒度：audit 窗口要足以暴露启动/取消差异，core 窗口要保持高 DOP 的正收益；两者需要量级平衡。
6. 每个模板必须声明主数据集、辅助数据集、业务语义、参数边界和 DOP 意图；生成器拒绝未知参数，避免静默 fallback。
7. 候选只有在两次独立运行、24 样本/模式、全部固定 DOP、mean/median/P99、结果 digest 和 trace 校验全部通过后，才能进入默认认证集。

## 失败案例与适用边界

- 纯健康 TPC-H 的 return-flag 集合差中，DOP=8 约 0.758 秒，优于 DOP=1 的约 0.875 秒。`EXCEPT -> DOP=1` 不是通用规则。
- 一个完全使用 SSB 的区域利润 + 原生 stage audit 组合，相对最佳固定 DOP 的中位提升只有 **13.346%**，未进入认证集。其独立 audit 虽然明显负扩展，但与业务 core 合并后的占比不足。
- 百万级供应商高基数版本对固定 DOP=2 的短筛提升只有约 **24.8%**；改为实际常见的供应国 × 运输方式 × 季度风险聚合后才稳定通过。
- 六输入集合验收使低 DOP 路径本身过重，未形成更好的整体权衡。输入越多并不意味着 fragment 级策略越有利。
- 本轮正式认证使用并发度 1，用于隔离单查询 fragment 调度效果；结果不能直接当作高并发吞吐结论。若用于线上容量规划，应另做并发阶梯和资源隔离实验。

因此，30% 结论严格限定在本报告的数据分布、查询拓扑和实验配置内。纯原生 SSB 查询未通过的事实说明，这一方法不能被泛化为“对任意数据集构造一个 EXCEPT 就会加速”。
